За что отвечает dotnet?
dotnet — это основной инструмент CLI для работы с .NET. Его ключевые функции:
dotnet — это командная строка (CLI, Command Line Interface) для работы с платформой .NET, разработанной Microsoft. .NET — это фреймворк для создания приложений, включая веб-приложения (например, ваше ValeraApi), консольные приложения, мобильные приложения и многое другое. dotnet используется для создания, сборки, запуска и тестирования проектов .NET.
Создание проектов: Используя dotnet new, можно создавать проекты на основе различных шаблонов (webapi, mvc, console, xunit и т.д.).
Сборка проектов: Команда dotnet build компилирует код в исполняемые файлы.
Запуск приложений: dotnet run запускает приложение.
Управление зависимостями: dotnet add package добавляет NuGet-пакеты, а dotnet add reference — ссылки на другие проекты.
Тестирование: dotnet test запускает unit-тесты.
Публикация: dotnet publish создаёт готовую к развертыванию версию приложения.
Управление решениями: dotnet sln позволяет работать с файлами решений (.sln).
dotnet new webapi -n ValeraApi
Создаёт новый проект Web API с именем ValeraApi.
dotnet add package xUnit
Добавляет NuGet-пакеты (например, для тестирования).
Почему тесты в отдельном проекте?

Тестовый проект (ValeraApi.Tests) отделён от основного (ValeraApi), чтобы:

Изолировать тесты от производственного кода (код API не смешивается с тестами).
Упростить тестирование, не включая зависимости API (например, веб-сервер или базу данных).
Обеспечить независимость: тесты проверяют только логику, а не всю систему.

После запуска API будет доступен по адресу, указанному в консоли (обычно https://localhost:5001 или http://localhost:5000).
ASP.NET Core Web API — это инструмент для создания веб-приложений, которые могут принимать запросы через интернет (например, от браузера или мобильного приложения) и отправлять ответы, обычно в формате JSON (простой текст с данными). Это как "посредник", который позволяет твоему приложению общаться с другими программами.
Представь, что это как меню в ресторане: клиент (например, твой телефон) делает заказ (запрос), а кухня (твой код) готовит еду (данные) и отправляет её обратно.
Основные черты:

Создаёт API: API — это набор команд, которые можно отправить серверу, например, "поменяй здоровье Валеры" или "дай мне текущее состояние Валеры".
Работает в интернете: Использует HTTP-запросы (GET, POST и т.д.) для общения.
Кроссплатформенный: Работает на Windows, macOS, Linux.
Простота: Легко настроить и расширить.
API состоит из контроллеров (обрабатывают запросы), моделей (представляют данные), сервисов (содержат бизнес-логику) и других компонентов.
В вашем проекте ValeraApi вы создаёте API, которое управляет состоянием персонажа Валеры (например, его здоровьем, уровнем алкоголя и т.д.).
n-layer (многоуровневая архитектура) — это способ организации кода, при котором
приложение разделяется на несколько слоёв (уровней), каждый из которых выполняет
строго определённую роль.
Классическая структура (3 слоя):
1. Presentation Layer (слой представления)
○ Принимает запросы от пользователя и возвращает ответы.
○ В нашем проекте — это будут контроллеры (папка Controllers).
2. Business Logic Layer (BLL, слой бизнес-логики)
○ Здесь описаны правила поведения системы.
○ Например: «Валера может пойти на работу только если алкоголь < 50 и
усталость < 10».
○ В нашем проекте — это будет папка Services.
3. Data Access Layer (DAL, слой доступа к данным)
○ Хранение и загрузка данных (обычно база данных).
○ В проекте — это будет папка Data.
Зачем использовать n-layer?
● Разделение ответственности: каждый слой отвечает за свою задачу.
● Масштабируемость: легко добавлять новые функции.
● Тестируемость: можно проверять бизнес-логику отдельно от БД и API.
● Гибкость: можно поменять базу данных или UI, не переписывая всё
приложение.
Data Access Layer (DAL): взаимодействие с базой данных или хранилищем (в вашем проекте пока не используется).
Дополнительно:
● Models (Domain layer) — предметная область (например, класс Valera).
● DTOs — специальные объекты для передачи данных между слоями.
Описание: decimal — это тип данных для хранения чисел с высокой точностью, включая дробную часть. Он предназначен для финансовых расчётов или других случаев, где важна точность десятичных чисел.
Тесты написаны с использованием фреймворка xUnit (это стандартный инструмент для unit-тестирования в .NET). Каждый тест следует паттерну AAA (Arrange — подготовка, Act — действие, Assert — проверка), что делает их читаемыми и структурированным
Каждый тест — это метод класса ValeraTests, помеченный [Fact]. Атрибут [Fact] говорит xUnit: "Это тест, запусти его". Тесты проверяют конкретные сценарии из бизнес-логики Valera (например, "что происходит, если Валера идёт на работу с низким алкоголем?").

Все тесты следуют паттерну AAA:

Arrange: Подготовка данных (создание объекта Valera с нужными значениями).
Act: Выполнение действия (вызов метода, например, valera.GoToWork()).
Assert: Проверка результата (использование Assert.Equal для сравнения ожидаемого и фактического значения).
